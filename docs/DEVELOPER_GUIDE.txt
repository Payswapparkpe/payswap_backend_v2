================================================================================
PAYSWAP BACKEND - DEVELOPER GUIDE
================================================================================

This guide provides essential information for developers working on the Payswap
backend codebase.

================================================================================
PROJECT STRUCTURE
================================================================================

core/
  - settings.py: Django settings and configuration
  - config.py: Pydantic-based configuration management
  - urls.py: Root URL configuration
  - celery.py: Celery configuration

portal/
  - models.py: User, Profile, Role, Wallet, KYC models
  - views.py: Authentication, profile, settings views
  - forms.py: User creation, signup, password management forms
  - admin.py: Django admin customization
  - services/: Business logic services
    - notification_service_v2.py: Unified SMS/Email service
    - otp_service.py: OTP generation and verification
  - utils/: Utility functions
    - user_utils.py: Username generation, role utilities
    - phone_utils.py: Phone number normalization
    - encryption.py: Data encryption utilities
    - logging_helper.py: Secure logging with data masking
  - tasks/: Celery background tasks
    - notification_tasks.py: Async SMS/Email sending
    - logging_tasks.py: Async logging
  - management/commands/: Django management commands
    - createsuperuser.py: Custom superuser creation
    - seed_data.py: Database seeding
    - setup_roles.py: Role and permission setup

api/
  - v1/, v2/: API version endpoints
  - authentication.py: API authentication
  - permissions.py: API permissions

================================================================================
KEY ARCHITECTURAL DECISIONS
================================================================================

1. USER-PROFILE SEPARATION
   - User model: Only credentials and login details
   - Profile model: All demographic, personal, banking, settings data
   - One-to-one relationship: Every user must have a profile
   - Email and phone stored in Profile, not User

2. USERNAME GENERATION
   - Auto-generated, cryptographically secure
   - Format: [RolePrefix]00[8 random alphanumeric]
   - Example: A00786543 (Admin), C00912345 (Customer)

3. ROLE-BASED ACCESS CONTROL
   - All users must have a role
   - Roles: admin, super, employee, distributor, retailer, customer, vendor
   - Permissions assigned via Role model
   - MFA required for certain roles

4. PHONE NUMBER FORMAT
   - Internal format: 91XXXXXXXXXX (no + sign)
   - Kaleyra API format: +91XXXXXXXXXX (with + sign)
   - Always prefix 91 for Indian mobile numbers

5. NOTIFICATION SERVICE
   - Unified NotificationServiceV2 for SMS and Email
   - Celery-based async processing
   - Secure logging with data masking
   - Phone numbers and emails masked in logs

================================================================================
DEVELOPMENT WORKFLOW
================================================================================

SETUP:
  1. Create virtual environment: python -m venv .venv
  2. Activate: source .venv/bin/activate
  3. Install dependencies: pip install -r requirements.txt
  4. Copy .env.example to .env and configure
  5. Run migrations: python manage.py migrate
  6. Setup roles: python manage.py setup_roles
  7. Seed data (optional): python manage.py seed_data

CREATING SUPERUSER:
  Since Django's default createsuperuser doesn't work with our custom User model,
  use one of these methods:

  Method 1 - Django Shell:
    python manage.py shell
    >>> from portal.models import User, Profile, Role
    >>> from portal.utils.user_utils import generate_username, get_role_prefix
    >>> role = Role.objects.get(code='admin')
    >>> username = generate_username(get_role_prefix('admin'))
    >>> user = User.objects.create_user(username=username, password='...',
    ...     role_code='admin', role=role, is_staff=True, is_superuser=True)
    >>> Profile.objects.create(user=user, first_name='Admin',
    ...     email='admin@payswap.in', phone='919876543210', type='individual')

  Method 2 - Management Command (direct):
    python manage.py shell
    >>> from portal.management.commands.createsuperuser import Command
    >>> cmd = Command()
    >>> cmd.handle(first_name='Admin', phone='919876543210',
    ...     email='admin@payswap.in', role_code='admin',
    ...     password='SecurePass123!', noinput=True)

RUNNING TESTS:
  python manage.py test
  python manage.py test_all
  python manage.py test_notifications --phone 919876543210 --email test@example.com

================================================================================
IMPORTANT MODELS
================================================================================

User (portal.models.User):
  - Fields: username, password, role_code, role, is_staff, is_superuser
  - Properties: email, phone, first_name (read from Profile)
  - REQUIRED_FIELDS: [] (email/phone in Profile)

Profile (portal.models.Profile):
  - Fields: user, first_name, last_name, email, phone, address, banking details
  - Unique: email, phone
  - Required: first_name, email, phone

Role (portal.models.Role):
  - Fields: code, name, permissions
  - Codes: admin, super, employee, distributor, retailer, customer, vendor

Wallet (portal.models.Wallet):
  - Fields: user, balance, currency
  - Transactions: WalletTransaction model

================================================================================
SERVICES AND UTILITIES
================================================================================

NotificationServiceV2 (portal.services.notification_service_v2):
  - send_sms(phone, message, async_send=True)
  - send_email(to_email, subject, message, async_send=True)
  - send_otp(phone, user_id=None, async_send=True)
  - All methods support sync/async modes

OTPService (portal.services.otp_service):
  - send_otp(phone, user_id=None, async_send=True)
  - verify_otp(phone, otp) -> bool
  - Rate limiting via Redis cache

Phone Utilities (portal.utils.phone_utils):
  - normalize_phone_number(phone, country_code='91') -> '91XXXXXXXXXX'
  - format_phone_for_kaleyra(phone) -> '+91XXXXXXXXXX'
  - is_valid_indian_mobile(phone) -> bool

User Utilities (portal.utils.user_utils):
  - generate_username(role_prefix) -> 'A00786543'
  - get_role_prefix(role_code) -> 'A', 'C', etc.

Encryption (portal.utils.encryption):
  - encrypt_data(data) -> encrypted string
  - decrypt_data(encrypted_string) -> original data
  - Used for: banking details, security questions, backup codes

Logging (portal.utils.logging_helper):
  - SecureLogger: Masks sensitive data in logs
  - sanitize_sensitive_data(data): Masks phone, email, passwords, API keys
  - All logging via Celery tasks for async processing

================================================================================
API INTEGRATIONS
================================================================================

Kaleyra SMS (portal.services.vendors.kaleyra):
  - India-specific endpoint: https://api.in.kaleyra.io/v1/{sid}
  - Message type: TXN (transactional)
  - Phone format: +91XXXXXXXXXX
  - Used for: OTP, transactional SMS

AWS SES (portal.services.vendors.aws_ses):
  - Email sending via SMTP
  - Templates: portal/templates/portal/emails/
  - Used for: Verification, notifications, password reset

AWS S3 (portal.services.vendors.aws_s3):
  - Document storage
  - KYC document uploads

================================================================================
CELERY TASKS
================================================================================

All async operations use Celery:
  - SMS sending: send_sms_task
  - Email sending: send_email_task
  - OTP sending: send_otp_sms_task
  - Logging: log_user_action_task

Configuration: core/celery.py
Broker: Redis
Result Backend: Redis

================================================================================
SECURITY CONSIDERATIONS
================================================================================

1. Password Storage: Django's PBKDF2 hashing
2. Sensitive Data: Encrypted at rest (banking, security questions)
3. Logging: All sensitive data masked in logs
4. MFA: Required for admin, super, employee roles
5. Rate Limiting: OTP rate limiting via Redis
6. Phone Validation: Indian mobile number validation
7. Email Validation: Standard email format validation

================================================================================
TROUBLESHOOTING
================================================================================

Issue: createsuperuser fails with "Role is required"
  Solution: Use Django shell method (see CREATING SUPERUSER above)

Issue: Phone number format errors
  Solution: Always use normalize_phone_number() before storing/using

Issue: OTP not sending
  Solution: Check Redis connection, Kaleyra credentials, phone format

Issue: Email not sending
  Solution: Check SMTP settings in .env, AWS SES credentials

Issue: Command not found
  Solution: Ensure virtual environment is activated, dependencies installed

ENVIRONMENT VARIABLES
================================================================================

Required in .env:
  - DATABASE_URL: PostgreSQL connection string
  - REDIS_URL: Redis connection string
  - SECRET_KEY: Django secret key
  - KALEYRA_SID: Kaleyra account SID
  - KALEYRA_API_KEY: Kaleyra API key
  - SMTP_HOST, SMTP_PORT, SMTP_USER, SMTP_PASSWORD: Email settings
  - AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY: AWS credentials
  - AWS_STORAGE_BUCKET_NAME: S3 bucket name

See .env.example for full list.
